# Implement stateless MCP 2026-07-28

Status: active; design complete, implementation not started

## Goal

Ship a dual-era stdio MCP server on macOS, Linux, and Windows that conforms to MCP `2026-07-28`, preserves `2025-03-26` clients, and replaces modern action tools' implicit process-memory snapshot dependency with an explicit `snapshot_ref` returned by `get_app_state` and successor action results.

## Scope

- Included:
  - final MCP `2026-07-28` request and result envelopes;
  - `server/discover`, inline version errors, result identity, deterministic tool lists, and cache hints;
  - dual-era stdio compatibility with the existing `2025-03-26` handshake;
  - explicit snapshot handles, lifecycle bounds, action revalidation, and concurrency control;
  - era-specific tool schemas and structured results;
  - shared behavioral fixtures across Swift and Go;
  - official MCP conformance plus legacy regression coverage;
  - user, architecture, reliability, security, and release documentation.
- Not included:
  - Streamable HTTP, OAuth, remote hosting, or load balancer deployment;
  - MCP Tasks, extensions, subscriptions, sampling, elicitation, roots, or MRTR;
  - changes to native input techniques or accessibility-tree rendering except where needed for handle validation;
  - immediate removal of legacy implicit snapshot behavior;
  - adoption of a Node sidecar or a new runtime dependency.

## Risks and mitigations

- Risk: a stale element index causes input on the wrong UI element.
  - Mitigation: require a modern `snapshot_ref`, bind it to PID/window/generation, and never recapture before dispatching an old index.
- Risk: a native action has an uncertain outcome and is repeated.
  - Mitigation: invalidate the handle once dispatch outcome is uncertain and require a new observation.
- Risk: cached screenshots and accessibility objects grow without bound.
  - Mitigation: absolute TTL, one live generation per target, global capacity, tombstones without payloads, and deterministic eviction.
- Risk: protocol behavior diverges across the three implementations.
  - Mitigation: shared raw JSON golden fixtures and normalized response comparisons in CI.
- Risk: a modern change breaks existing hosts.
  - Mitigation: select behavior by protocol era and retain byte-compatible legacy responses.
- Risk: app-agent connections race on shared state.
  - Mitigation: a single store owner plus per-target action serialization and generation compare-and-swap.
- Risk: SDK guidance changes during implementation.
  - Mitigation: pin tests to final `2026-07-28` schemas and record any SDK adoption as a separate plan decision.

## Milestones

### M0 — Freeze behavior and fixtures

Deliverables:

- capture representative current legacy transcripts for initialize, tool list, successful call, tool error, unknown method, and turn-ended notification;
- add modern request/response fixtures derived from the final schema;
- define a normalization rule for object key order, timestamps, versions, random handles, and platform-only fields;
- make the fixture runner fail if stdout contains a non-JSON diagnostic.

Exit criteria:

- all three platforms pass the legacy fixtures before production behavior changes;
- the modern fixtures initially fail for documented reasons.

### M1 — Dual-era protocol adapter

Deliverables:

- introduce `ProtocolEra`, per-request envelope parsing, error constants, and response decoration;
- implement `server/discover` and direct modern dispatch;
- require modern protocol version and client capabilities on every request;
- stamp `resultType: "complete"` and result `_meta` centrally;
- add `ttlMs: 300000` and `cacheScope: "public"` to modern discover and tool-list results;
- remove modern `ping` while preserving legacy `ping`;
- keep project-specific turn-ended cleanup best-effort in both modes;
- preserve legacy initialization and response shapes.

Suggested commit boundary: `feat(mcp): add dual-era 2026-07-28 protocol adapter`

Exit criteria:

- modern protocol fixtures pass on Swift and both Go binaries;
- legacy transcripts remain unchanged;
- two direct modern requests can be handled without initialize and with different client capability objects.

### M2 — Structured results and era-specific schemas

Deliverables:

- add optional `structuredContent` to tool result types on every platform;
- create deterministic legacy and modern tool catalogs;
- add required `snapshot_ref` to every modern action schema;
- add the snapshot output schema or an equivalent checked JSON shape for `get_app_state` and action results;
- include the handle in both visible text and structured content;
- update server instructions to describe the explicit state chain in modern mode.

Suggested commit boundary: `feat(tools): define explicit snapshot reference contract`

Exit criteria:

- `tools/list` is stable byte-for-byte after normalization;
- all seven action schemas require `snapshot_ref` only in modern mode;
- existing legacy schema tests pass.

### M3 — Snapshot handle store

Deliverables:

- implement opaque 192-bit handle generation;
- implement fake-clock-friendly TTL and deterministic capacity enforcement;
- record app, PID, window, pixel scale, generation, element records, and lifecycle state;
- implement redacted diagnostics and lightweight tombstones;
- move macOS ownership from each connection/server into the app-agent runtime;
- add equivalent explicit store ownership to Linux and Windows.

Suggested commit boundary: `feat(computer-use): add bounded snapshot handle store`

Exit criteria:

- unit tests cover mint, resolve, expiry, eviction, unknown values, and restart behavior;
- no log or error includes a full handle or captured UI content;
- closing a macOS socket connection does not delete live handles while the app agent remains alive.

### M4 — Transactional modern actions

Deliverables:

- pass an explicit `SnapshotContext` through the dispatcher into every action;
- validate handle, app identity, PID, window, coordinate bounds, generation, and action-specific native properties before input;
- serialize actions per target and implement `live` → `in_flight` → `superseded` transitions;
- mint and return a successor handle after every successful action;
- distinguish retryable pre-dispatch failures from uncertain dispatch and refresh failures;
- keep the legacy `currentSnapshot` path isolated and clearly marked for later deprecation.

Suggested commit boundary: `feat(computer-use): bind modern actions to snapshot generations`

Exit criteria:

- a stale/concurrent/mismatched handle causes zero native input;
- two concurrent uses of one handle never perform two actions;
- a successful action returns a usable successor generation;
- no modern action calls an implicit fresh-snapshot fallback before dispatch.

### M5 — Integration, conformance, and release readiness

Deliverables:

- extend the smoke suite with a modern client path;
- run the official MCP server conformance suite with `2026-07-28`;
- validate a Tier 1 SDK client in pinned-modern, auto, and legacy modes;
- run macOS fixture automation plus Linux and Windows tests;
- update architecture, reliability, security, README/setup, troubleshooting, and release notes;
- add a history document and move this plan to `completed/` only after all exit criteria pass.

Suggested commit boundary: `test(mcp): verify stateless protocol and snapshot lifecycle`

Exit criteria:

- every acceptance criterion in the design document is checked;
- CI is green on all supported platforms;
- unsupported optional conformance cases are documented and are not core failures;
- rollback instructions are tested and the compatibility window is documented.

## Validation commands

Commands may evolve as the fixture and conformance runners are added. Update this section with exact working invocations during implementation.

```bash
./scripts/check-docs.sh

swift test
(cd apps/OpenComputerUseLinux && go test -count=1 ./...)
(cd apps/OpenComputerUseWindows && go test -count=1 ./...)
./scripts/run-tool-smoke-tests.sh
./scripts/test-mcp-protocol-fixtures.sh
```

`swift test` runs from the repo root: only `Package.swift` is at the root, so
`--package-path packages/OpenComputerUseKit` is wrong. Each Go module is its own
directory with no repo-root module, so the Go suites run from inside each app
directory. `./scripts/run-tool-smoke-tests.sh` is the real smoke entry point;
`./scripts/smoke-all.sh` does not exist. `./scripts/test-mcp-protocol-fixtures.sh`
is delivered in M0.

Still planned (not yet delivered):

```bash
./scripts/test-mcp-conformance.sh --spec-version 2026-07-28
```

Manual checks:

- inspect a modern `server/discover` response before any initialization;
- perform `get_app_state` → action → action with successor handles;
- attempt reuse of the first handle and confirm no input occurs;
- wait past TTL and confirm the recovery message calls for a new state;
- run one existing client that only knows the `2025-03-26` handshake;
- restart the macOS app agent between state and action and confirm safe failure.

Observability checks:

- stdout contains JSON-RPC only;
- stderr reports era, method, result, duration, generation, and a redacted handle suffix;
- no screenshot, accessibility text, typed input, full handle, or full client metadata appears in logs.

## Decision record

- 2026-08-13: support `2026-07-28` and the already implemented legacy `2025-03-26`; do not claim `2025-11-25` compatibility without its full semantics.
- 2026-08-13: preserve stdio as the only public MCP transport for this migration.
- 2026-08-13: use explicit opaque snapshot handles backed by the permission-bearing device runtime rather than serializing native UI state into tokens.
- 2026-08-13: require `snapshot_ref` for all modern action tools, including coordinate and keyboard tools, because each depends on observed window/focus state.
- 2026-08-13: keep legacy implicit snapshot behavior temporarily to avoid an unrelated breaking change.
- 2026-08-13: use one live generation per app/window and invalidate uncertain outcomes; correctness takes priority over transparent retries.
- 2026-08-13: implement the small protocol surface in the repository first and reconsider official SDK adoption after conformance, avoiding a simultaneous runtime/dependency migration.
- 2026-08-13: publish no remote changes until GitHub credentials are valid; local work remains fully reviewable in the clone.
- 2026-08-18: era classification serves a first request without modern `_meta` as legacy instead of rejecting it; the design's ambiguous-reject row contradicts byte-compatible legacy behavior. Cross-era stickiness is enforced in both directions.
- 2026-08-18: measured snapshot memory (design open question 2): about 938 KB per snapshot at the 900 KB screenshot cap, about 15 MB worst case at 16 live targets; the 16-target cap is unchanged.
- 2026-08-18: on Linux and Windows, native dispatch resolves the stored runtimeId path and the runtime script verifies role/name before acting; a mismatch aborts with `snapshot_target_changed` and performs no input. Native references cannot survive the stateless interpreter boundary on those platforms.
